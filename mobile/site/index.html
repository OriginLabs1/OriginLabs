Trust boundary

Rust is not a dependency. It is the proof.

Canonical JSON, SHA-256, event construction and chain verification exist in one place: a std-only Rust crate with no third-party crates. It compiles to a native CLI for tests and to WebAssembly for the app.

One implementation, two targets

The same source file produces both artifacts. The app refuses to run without the core; there is no JavaScript fallback for hashing.

What “verified” means

Every event’s hash is recomputed from canonical JSON, and each prev must match the previous hash. Change one byte and verification fails at that sequence.

  • Tamper-evident: the app’s Tamper test alters a copy and shows ok:false.
  • Not signed: principal labels are self-asserted; there is no device key yet.

How it works

Evidence, gates and a ledger that only grows.

No edits, no silent rewrites. Corrections are appended. Refused gates never enter the history.

01 · Ledger

Append-only by construction

Charters, claims, evidence, gates, artifacts and incidents form a hash chain. The writer refuses to extend a broken chain.

02 · Evidence

Floors, not vibes

E1 to investigate, E2 to support, E3 to establish, E4 for high-risk work. Confidence and falsifiers are recorded with the claim.

03 · Gates

Two humans or no transfer

Agents can never sign a gate. A Transfer requires two distinct human signers, checked before an event is built.

04 · Data classes

Class 2 stays a reference

Confidential payloads may carry hashes and references, never raw content or long free text. The policy is enforced before append.

05 · Offline

Nothing to phone home to

No INTERNET permission, no fetch in app scripts, network loads blocked in the WebView. The PWA is cache-first.

06 · Build

No Gradle, no AndroidX

aapt2, javac, D8, zipalign, apksigner. Zero npm dependencies, zero Rust crates. The whole pipeline is in the repo.

Verification

Check the download yourself.

Every release ships the APK, SHA-256 sums, the signing certificate, a release manifest and a CycloneDX SBOM.

# 1. checksums, next to the downloaded assets
sha256sum -c SHA256SUMS

# 2. signature and signer fingerprint
apksigner verify --verbose --print-certs \
  OriginLabs-0.0.1.apk

# 3. in the app
Lab → Run self-test  → PASS
Home → Verify chain  → ok:true
Home → Tamper test   → ok:false
  • Same signer every update. Android refuses an update signed with a different key.
  • Manifest, not marketing. release-manifest.json binds the APK, core and registry digests.
  • SBOM included. CycloneDX 1.5, generated by the release script.
  • Not bit-reproducible yet. Verify the signer and checksums, not a rebuild diff.
