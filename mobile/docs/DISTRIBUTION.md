# Distribution

OriginLabs v0.0.1 is distributed through channels that need no account, no
payment and no proprietary store:

| Channel | Address | What you get |
| --- | --- | --- |
| GitHub Releases | `https://github.com/OriginLabs1/OriginLabs/releases/latest` | signed APK, checksums, manifest, SBOM, web zip, core builds |
| GitHub Pages | `https://originlabs1.github.io/OriginLabs/` | installable PWA, identical code, no install permission |
| Obtainium | `https://apps.obtainium.imranr.dev/redirect?r=obtainium://add/https://github.com/OriginLabs1/OriginLabs` | automatic APK updates from Releases |
| Direct APK | the release asset `OriginLabs-0.0.1.apk` | sideload on Android 10+ |
| F-Droid | `mobile/fdroid/` (draft, not submitted) | free build recipe for a future listing |

Package identity: `com.oneorigin.labs` · version `0.0.1` · `versionCode 1` ·
`minSdk 29` · `targetSdk 34` · zero permissions.

## Release assets

`node mobile/scripts/release.mjs` assembles `mobile/release/` from the built
artifacts:

```
OriginLabs-0.0.1.apk                     signed universal APK
OriginLabs-0.0.1.apk.sha256              digest only, for a quick check
SHA256SUMS                               every asset, `sha256sum -c` format
signing-certificate.txt                  keytool output and SHA-256 fingerprint
release-manifest.json                    versions, hashes, links, signature
originlabs-0.0.1.cdx.json                CycloneDX 1.5 SBOM
OriginLabs-0.0.1-web.zip                 static PWA, unzip and serve anywhere
origin-core-0.0.1-wasm32.wasm            the trust core for other clients
origin-core-0.0.1-aarch64-unknown-linux-gnu   native CLI core
```

`release-manifest.json` is the machine-readable index: app and core versions,
the registry digest, the wasm SHA-256, the APK SHA-256 and size, the signer
certificate fingerprint, the git commit (when available) and the public URLs.
It is the file to parse if you are writing another client.

## Publishing v0.0.1

The release workflow is `.github/workflows/release.yml`. It triggers on a tag
matching `v*` and needs three repository secrets:

| Secret | Value |
| --- | --- |
| `ORIGINLABS_KEYSTORE_BASE64` | `base64 -w0 mobile/keys/originlabs.p12` |
| `ORIGINLABS_STORE_PASSWORD` | value from `mobile/keys/keystore.properties` |
| `ORIGINLABS_KEY_PASSWORD` | same value (PKCS#12 uses one password) |

Tag and push:

```sh
git tag -a v0.0.1 -m "OriginLabs v0.0.1"
git push origin main
git push origin v0.0.1
```

The workflow builds the core native and for wasm32, runs all tests, builds the
web surface, signs the APK with the release key, runs `release.mjs`, and creates
the GitHub release with every asset attached plus the release notes.

Without a tag workflow, publish manually:

```sh
cd mobile
./scripts/build-wasm.sh
node scripts/gen-icons.mjs
node scripts/build-web.mjs
./scripts/build-apk.sh
node scripts/release.mjs
cd ../..
gh release create v0.0.1 mobile/release/* \
  --repo OriginLabs1/OriginLabs \
  --title "OriginLabs v0.0.1" \
  --notes-file mobile/docs/RELEASE-NOTES-0.0.1.md
```

If `gh` is unavailable, create the release in the GitHub web UI and upload every
file in `mobile/release/`. The release must contain the APK; the other assets
are verification material.

## GitHub Pages

`.github/workflows/pages.yml` builds the core and web surface, then publishes
`mobile/site/` as the Pages artifact. Enable it once under
**Settings → Pages → Build and deployment → Source: GitHub Actions**.

`mobile/site/index.html` is the landing page. `mobile/site/app/` is the PWA and
is regenerated by `build-web.mjs`; do not hand-edit it. The app works offline
after the first load through its service worker, and the service worker is
cache-first so a version bump also bumps `CACHE` in `web/sw.js`.

Pages serves the same code as the APK. The only behavioural difference is that
the PWA has no Android bridge, so exports download as files instead of using
the share sheet.

## Obtainium

Obtainium adds the repository as an app source and reads GitHub Releases:

1. Open the Obtainium link above, or add
   `https://github.com/OriginLabs1/OriginLabs` manually.
2. Let Obtainium filter release assets: the APK is the only `.apk` asset, so the
   default "APK" filter works. No API key, account or GitHub login is required.
3. Updates are checksum-verified by Android's package manager through the
   signing certificate. Keep using releases signed by the same key.

Because the app declares no permissions and no network access, Obtainium is only
the delivery mechanism; the app never contacts GitHub itself.

## F-Droid

`mobile/fdroid/metadata/com.oneorigin.labs.yml` is a **draft** build recipe, not
an accepted listing. F-Droid builds from source on its own infrastructure and
requires the recipe to succeed there; the metadata currently points at
`mobile/` and calls the same scripts with a throwaway keystore. Before submitting:

- tag the exact commit (`v0.0.1`) and set `commit:` to it,
- confirm the buildserver has Rust with the wasm32 target (otherwise vendor the
  wasm build step or build the core natively for the host),
- add fastlane metadata (description, icon, screenshots) under
  `mobile/fdroid/metadata/en-US/`,
- open a merge request against `fdroiddata` and expect review comments.

Until then, F-Droid is not a supported channel and no listing exists.

## Verifying a download

```sh
sha256sum -c SHA256SUMS
apksigner verify --verbose --print-certs OriginLabs-0.0.1.apk
```

The certificate SHA-256 for v0.0.1 is printed by the release workflow and stored
in `signing-certificate.txt`. For the key generated on this machine it is:

```
76:6E:F7:D9:21:E7:E9:F7:58:79:D3:56:36:29:28:86:2A:7C:92:31:CB:08:AC:08:BD:DA:CA:5B:61:28:CE:DC
```

Compare the fingerprint, not just "verified": anyone can sign an APK, only the
holder of the release key can sign an update that Android will accept.

You can also verify the app's own claims offline: install it, open the demo lab,
run **Verify chain**, then **Tamper test**. The second check alters one byte in a
copy and shows the Rust core rejecting it.

## Versioning and updates

- `versionName` follows `0.0.x` for this series; `versionCode` is a monotonically
  increasing integer starting at `1`.
- Update `app/src/main/AndroidManifest.xml`, `web/data/build.json` generation in
  `scripts/build-web.mjs` if the version is read from there, `mobile/web/sw.js`
  (`CACHE`), and the release notes.
- Never reuse a `versionCode`.
- Never change the application ID. A rename is a new app, not an update.
- Keep the keystore and its passwords offline and backed up. Losing them means
  no future update can be installed over v0.0.1.
